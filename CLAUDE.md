# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

An ECG heartbeat classifier (Normal vs. Abnormal) trained on the MIT-BIH Arrhythmia Database, quantized to INT8, and deployed for on-device inference on an ESP32-S3 via TensorFlow Lite Micro. The project has three stages that live in three different places:

1. **Training** — the `ecg/` package + `scripts/train.py`, runs locally. (`train_pipeline.ipynb` is the original Colab notebook this was extracted from; it's superseded and kept only as a Colab-runnable reference — see the note at the top of the notebook.)
2. **Generated artifacts** — `artifacts/ecg_multiscale_model.keras`, `artifacts/model_int8.tflite`, `artifacts/threshold.json`, `artifacts/metrics.json`, `artifacts/per_record_metrics.csv`, `artifacts/val_per_record_metrics.csv`, `deployment_model/model_data.h`, `deployment_model/threshold.h` — all produced by `scripts/train.py`. Not sources of truth; regenerate rather than hand-edit.
3. **Firmware** — `deployment_model/deployment_model.ino`, an Arduino sketch for the ESP32-S3 that loads `model_data.h` + `threshold.h` and runs inference.

## Commands

python scripts/train_cv.py --seeds 45 46 --classes nsv --artifacts-dir artifacts/dechazal/stage2/step3_nsv_matched  # step 3 reference; its seeds 42-44 are copies of step2a_nsv_matched's runs
python scripts/train_cv.py --seeds 42 43 44 45 46 --classes nsv --rr-lookback 30 --artifacts-dir artifacts/dechazal/stage2/step3a_rr30  # step 3a
python scripts/analyze_splits.py    # read-only val/test split diagnosis with the saved models -> artifacts/split_analysis/
python scripts/analyze_splits.py --counts-only  # beat composition per split only, no models (use after a split change)

## Working with the `ecg` package

- **`ecg/data.py`**: `ensure_mitdb_cached` / `load_record` download and cache MIT-BIH records under `<data_dir>/mitdb` (only the records actually needed, not the full 48-record database); `build_dataset` orchestrates loading + feature extraction across a record list and returns `X_spec, X_rr, y, record_ids`. Train/val/test splits are the de Chazal inter-patient split, hardcoded in `scripts/train.py`: test = DS2 exactly, train + val = DS1, and paced records 102/104/107/217 are excluded. Val is `115, 122, 207, 220, 223`, carved out of DS1 by patient. 207 is the only LBBB record in val (109 is in train), 220/223 carry S and V beats, and 115/122 are normal-only. Rationale and limitations are in README.md, "Data split". `tests/test_splits.py` enforces the split's invariants, so change the lists only together with that test. One known same-patient exception: 201 (train) and 202 (test). It is kept for comparability with the published split; 201 must never move to val, and `train.py` also reports test metrics `*_excl_202`. `max_normal_per_record` caps normal beats for train (class-balance control); val/test pass `None` (no cap) so reported metrics reflect the real class distribution. `build_dataset` reads the MLII lead by signal name (`LEAD`, `lead_index`), not channel 0. Record 114 stores V5 in channel 0, and is the only DS1/DS2 record that does. This is Stage 2 step 1b. `lead=None` reproduces the pre-fix channel-0 behavior (`diagnose_s_beats.py` is pinned to it). `tests/test_data.py` checks every DS1/DS2 record against header fixtures in `tests/fixtures/mitdb_headers/`.
- **`ecg/features.py`**: pure signal-processing functions, no I/O — `SYMBOL_MAP` (binary relabeling: 0 = Normal `N,L,R,e,j`; 1 = Abnormal `V,E,A,a,J,S`), `bandpass_filter` (0.5–40 Hz Butterworth), `compute_spectrogram` (STFT, `nperseg=64, noverlap=48`, normalized), `compute_rr_timing_features` (`pre_rr, post_rr, local_mean_rr, rr_ratio, pre_post_ratio`), `extract_beats_from_record` (windowing + R-peak-jitter augmentation, seeded via an injected `rng`). R-R intervals run between consecutive **beat** annotations only (`BEAT_SYMBOLS` / `beat_annotation_mask`; F and Q count as R-R neighbors but aren't extracted), and a beat is usable only with a beat annotation on each side. This is Stage 2 step 1. Before it, R-R also spanned non-beat annotations (`+`, `~`, `|`, `!`, ...), which affected 13% of N, 28% of S and 32% of V beats in DS1 (diagnosis.md, "Stage 1"). `rr_from_all_annotations=True` (also on `build_dataset`) reproduces the pre-fix features; use it only to reproduce runs made before the fix, e.g. `diagnose_s_beats.py`, which is pinned to it. `rr_quantile_ratio` is diagnosis-only; the median variant was tested and dropped. Kept I/O-free specifically so these are unit-testable with synthetic signals (see `tests/test_features.py`).
- **`ecg/model.py`**: `build_multiscale_ptq_model` + `focal_loss` — ported verbatim from the notebook, architecture/hyperparameters unchanged. Dual-input: two parallel Conv2D branches over the spectrogram (temporal `(1,5)` and spectral `(5,1)` kernels) concatenated, plus a Dense branch over the 5 R-R features, fused into a sigmoid output. `relu6` + L2 regularization specifically because the model targets INT8 PTQ — bounded activations quantize more cleanly. Focal loss (`gamma=2.0, alpha=0.25`) instead of plain BCE because Abnormal beats are the minority class. `focal_loss(alpha=None)` is unweighted (weight 1 on both classes, not alpha 0.5, which would halve the loss against L2). `categorical_focal_loss(gamma, class_weights)` is the softmax version with integer labels; its weights live in the loss because Keras `class_weight` doesn't reach `val_loss`, which early stopping monitors. `build_multiscale_bn_folded_model` is the same network reordered to Conv→BN→ReLU6 so BN folds into the conv at conversion; the baseline's BN-after-ReLU6 is the cause of its float→INT8 gap (see `artifacts/diagnosis.md`). **bn_folded is the architecture going forward** (diagnosis.md, "de Chazal split results"). On DS2 it matches the baseline's float PR-AUC with ~10× less seed variance and has no INT8 gap. `build_multiscale_bn_folded_model(n_classes=3)` gives the N/S/V softmax head (`features.NSV_CLASSES` order, labels from `nsv_labels`). Only the output layer depends on `n_classes`; `tests/test_model.py` pins the binary model's seed-42 initial weights to a digest from before the option existed, so step 1b stays a valid binary-matched cell. The baseline is retired from new experiments: keep `build_multiscale_ptq_model` and `--variant baseline` working for reproducibility, and keep existing baseline results as the historical record, but don't train baseline in CV, R-R normalization, calibration or multiclass runs (`train.py --variant` and `compare_variants.py --variants` default to bn_folded; name baseline explicitly only to reproduce).
- **`ecg/qat.py`**: QAT via tfmot, which needs tf_keras — only import it in a process started with `TF_USE_LEGACY_KERAS=1` (`scripts/train.py --variant qat` sets this itself before importing TF). Saved QAT models are `.h5`; tf_keras's `.keras` loader drops the quantize layers' variables.
- **`scripts/compare_variants.py`**: runs `train.py --no-firmware-export` once per variant in separate processes, writing to `artifacts/dechazal/variants/<run>/` and training every variant, baseline included. A saved model is reused only when passed explicitly via `--baseline-model`/`--load-model`, and it must come from the same split. `artifacts/variants/` and the committed files directly under `artifacts/` are the old-split record: don't write there; `--calib-samples` takes a list (each PTQ variant is trained once per seed, then re-converted per size). `--seeds` trains every variant once per seed (run dirs `<variant>[_calibN]_seed<S>`), and the tables add mean ± std per configuration. `--normalize-rr` is comparison-only until the firmware applies `rr_norm.h`.
- **`scripts/train_cv.py`** + **`ecg/cv.py`**: patient-grouped CV over DS1 (`CV_FOLDS` / `CV_ALWAYS_TRAIN` in `train.py`, invariants in `tests/test_splits.py`). Each of the 5 fold models early-stops on its held-out fold. The threshold comes from the pooled out-of-fold INT8 scores, and the final model trains on all 22 DS1 records for the median of the folds' best epochs, then is evaluated once on DS2. 201 is never held out, so threshold selection never sees the 201/202 patient. All thresholds run on `evaluate.abnormal_score` (P(abnormal), or 1 − P(N) for multiclass), so a multiclass model can reuse the CV. Runs go to `<artifacts-dir>/cv/<variant>_seed<S>/` (gitignored); tables to `<artifacts-dir>/cv_comparison.*` via `compare_variants.aggregate(..., CV_TABLE)`. `artifacts/dechazal/cv/` holds the pre-fix (all-annotation R-R) runs that Stage 1 diagnosed; Stage 2 runs each get their own `--artifacts-dir artifacts/dechazal/stage2/<step>/`. `train_cv.py` refuses to overwrite an existing run unless given `--overwrite`. `--classes {binary,nsv}`, `--loss-weights {matched,none,balanced}` and `--rr-lookback` (intervals averaged into `local_mean_rr`, default `features.RR_LOOKBACK` = 10, applied to the training, OOF and DS2 views alike; step 3a uses 30) pick the configuration. The defaults reproduce step 1b. Runs written before a flag existed read as its default. `balanced` (N/S/V only, step 2b) computes `features.balanced_class_weights` per training view and early-stops fold models on the unweighted val loss plus L2 (`train.fit_model(monitor_loss=...)`), not on its own S-heavy weighted val_loss. Every run records its per-fold and final weights, `loss_scale` and `early_stopping_monitor` in `folds.json` / `metrics.json`. Fold models early-stop on the very patients they're scored on, which makes all OOF metrics optimistic (diagnosis.md, "Known limitation: early stopping on the held-out fold"; nested validation parked). Each run records its configuration in `metrics.json`, and one `--artifacts-dir` holds one configuration (enforced). N/S/V runs also save `float_probs`/`int8_probs` (n, 3) in `oof_predictions.npz`; on DS2 their Se/+P come from `evaluate.predicted_classes` (N unless 1 − P(N) > t, else the likelier of S and V), with `S_as_V`/`V_as_S` mix-up counts. `predict_tflite` returns (n,) for binary output and (n, k) for k classes. `folds.json`'s per-fold DS2 numbers are diagnostic only, never used for any choice. The tables report AAMI `se_V`/`se_S`/`pp_V`/`pp_S` (`features.aami_class_metrics`); +P is NaN for a binary model by design, so don't substitute a binary proxy.
- **`ecg/export.py`**: `convert_to_int8_tflite` (INT8 PTQ via `TFLiteConverter`, calibration set is a **shuffled** sample of training data, not the first N in order); `write_c_header` (writes the TFLite flatbuffer as `deployment_model/model_data.h`); `write_threshold_header` (writes the chosen threshold as `deployment_model/threshold.h`, a `constexpr float kAbnormalThreshold`); `quantize_value`/`dequantize_value` (shared with `ecg/evaluate.py`, mirror the firmware's `quantize_float_to_int8`/`dequantize_int8_to_float`).
- **`ecg/evaluate.py`**: `select_threshold` sweeps thresholds on **validation** predictions from the **INT8** model (not the float model, not the test set — the INT8 model is what's actually deployed) and picks one by `strategy="f1"` (maximize Abnormal F1) or `"recall_at_precision"` (lowest threshold meeting a precision floor); `predict_tflite` runs the `.tflite` model via `tf.lite.Interpreter`, binding input/output tensors **by name substring**, not by index (unlike the firmware — see below); `evaluate_predictions` returns overall + per-record metrics (`zero_division=0`, with `n_abnormal` so a genuine 0 can be told apart from an undefined metric).

## Stage 2 workflow (current)

Stage 1 (diagnosis.md, "Stage 1") found that the S-beat failure is mainly in the training objective, plus an R-R input bug. Stage 2 fixes these in order of how fundamental they are. The full plan is in diagnosis.md, "Stage 2 plan". Follow it in order:

1. Beat-only R-R intervals in `extract_beats_from_record`, then retrain the CV baseline (binary bn_folded, focal gamma 2 / alpha 0.25). Done; see diagnosis.md, "Stage 2 step 1 results".
   **1b:** read MLII by signal name (record 114's leads are swapped), then retrain the same baseline. That run is the baseline for 2a.
2. **2a** (done; diagnosis.md, "Stage 2 step 2a results"): binary vs. N/S/V multiclass under two weightings, with focal gamma = 2 throughout. The pairs are unweighted (no alpha vs. no class weights) and matched (alpha 0.25 vs. N 0.75 / S 0.25 / V 0.25). N/S/V matched carries forward. **2b** (done; diagnosis.md, "Stage 2 step 2b results"): a three-way N/S/V comparison of nsv_unweighted, nsv_matched and nsv_balanced (inverse-frequency weights, frequency-weighted mean 1). No cell won on S PR-AUC, and balanced failed the V guard, so nsv_matched carries forward and the nsv_matched_normalized follow-up is skipped. The threshold stays on `abnormal_score` (1 − P(N)). Report +P for S and V once a multiclass model exists. Multiclass is N/S/V only (F and Q are dropped); say so in the README wherever results are compared with the literature.
3. **Step 3** (next; a gap remains after step 2): **3a** is a 30-interval R-R lookback against nsv_matched. **3b** is `--normalize-rr` on top of the 3a winner, or on top of nsv_matched if 3a has no winner. Every step 3 cell uses seeds 42–46, the nsv_matched reference included (seeds 45 and 46 added for step 3 only). The decision rule, the normalization's leakage checks and the firmware needs are fixed in diagnosis.md, "Step 3 design". After step 3, decide whether the SVDB/INCART training-data work starts before steps 4 and 5.
4. Global average pooling instead of Flatten. Flatten → Dense holds 197,184 of the ~202.2k parameters.
5. Re-measure the AF/flutter normal-beat FPs. Wide-QRS FPs and record 124's `J` beats are known limitations.

**Rules for every step:**
- One change at a time.
- Retrain under grouped CV with seeds 42, 43, 44 (42–46 from step 3 on).
- Decide only on OOF per-class (S vs N, V vs N) ROC-AUC and PR-AUC. Never use DS2 for a choice.
- A change counts only if its gain exceeds the measured seed-to-seed spread.
- Make the decision table with `scripts/compare_oof.py`, using the previous step's runs as the reference. The INT8 rows decide. For 2a, run it once per weighting row, with that row's binary run as the reference. Its P(S)/P(V) AUCs and S<->V counts are descriptive only, and its INT8-minus-float table is the quantization check.
- Report each step's results to the user before starting the next one.

**Parked:** Pan-Tompkins, DS2 sensitivity analysis, pruning, firmware header regeneration, calibration sweep, and fair QAT.

**Required before deployment (not yet fixed):** the final-model procedure, meaning the epoch count (median of the folds' best epochs) and the transfer of the pooled-OOF threshold to the final model. In step 1, seed 44's final model gave 12,917 DS2 FPs at its OOF threshold; seeds 42 and 43 gave 96 and 300. OOF decisions are unaffected. Don't export a model to firmware until this is fixed.

## Working with the firmware (`deployment_model/deployment_model.ino`)

- Targets ESP32-S3, built against `TensorFlowLite_ESP32` (TFLite Micro). `kTensorArenaSize` is fixed at 16 KB — if the model architecture grows, this must be increased or `AllocateTensors()` fails at runtime.
- Expects two input tensors: the spectrogram and the 5 R-R features; `output(0)` is the single sigmoid probability. The TFLite converter does **not** preserve the Keras `inputs=[spec_input, rr_input]` order — the current flatbuffer has `rr_input` at `input(0)` and `spectrogram_input` at `input(1)`. TFLite Micro has no name-based lookup, so `setup()` binds inputs by element count (the 5-element tensor is R-R) and refuses to run if binding fails. Don't go back to binding by index (contrast with `ecg/evaluate.py`, which binds by name substring).
- All I/O is INT8; `quantize_float_to_int8`/`dequantize_int8_to_float` do the float↔int8 conversion using the per-tensor `scale`/`zero_point` baked into the converted model, which change any time the model is re-trained/re-quantized.
- `loop()` currently feeds hardcoded dummy sensor data (`dummy_rr_features`, constant `0.5f` spectrogram) — real sensor acquisition/preprocessing to match `ecg/features.py`'s filtering + STFT pipeline is not yet implemented on-device.
- Alert threshold (`probability > kAbnormalThreshold`, from `threshold.h`) is generated by `scripts/train.py` from the same value recorded in `artifacts/threshold.json` — don't hardcode a threshold here; regenerate `threshold.h` instead.

## Deployment constraints

- The deployed firmware will detect R-peaks itself using Pan-Tompkins, not ground-truth annotations. Feature extraction should accept R-peak locations from any source (annotation-derived or detector-derived), so the model can later be evaluated using Pan-Tompkins detections on MIT-BIH instead of the expert annotations — not yet implemented.
